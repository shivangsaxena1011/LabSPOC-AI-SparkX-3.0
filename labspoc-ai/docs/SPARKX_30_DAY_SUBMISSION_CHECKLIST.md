# SparkX 3.0 — 30-Day Challenge Submission Checklist

## Challenge identity

- Event: SparkX 3.0 Beyond Boundaries
- Pathway: 30-Day AI Innovation Challenge (not SparkX Pro/Novel semester track)
- Domain 03: Smart Campus & Digital Twin
- Problem: AI-Powered Intelligent Lab SPOC (Virtual Lab Ambassador)
- Sprint window published on the event site: 15 October–15 November 2026
- Grand evaluation/showcase published: 26 November 2026 (Indian participants attend the on-campus event)
- Team size allowed by the published FAQ: 1–4; individual participation is within that range.

## Four mandatory deliverables published by SparkX

- [ ] Project presentation / slide deck.
- [ ] Live working prototype / product demonstration.
- [ ] Public GitHub repository with clear commit history.
- [ ] Comprehensive user manual / setup guide.

## Product demo checklist mapped to Domain 03

- [ ] Virtual guide: show real lab zones and select a hotspot tied to a real asset ID.
- [ ] Conversational assistant: ask a multi-turn question about an approved equipment manual.
- [ ] RAG knowledge: show retrieved evidence and source/page; demonstrate abstention when unsupported.
- [ ] Project demonstrator: show at least one approved project with actual outcomes/media/demo link.
- [ ] Visitor analytics: create a visit, record consent, ask a question, show aggregate event counts.
- [ ] Adaptive tour: generate 2-, 5- and 15-minute agendas for at least two visitor personas.

## Submission package hygiene

- [ ] ZIP includes source code, `.env.example`, setup docs and license; excludes `.env`, API keys, local DBs, uploads, `.venv`, `node_modules`, build output and personal data.
- [ ] Public GitHub repo uses MIT or Apache-2.0 license and meaningful commits.
- [ ] README has prerequisites, installation, run commands, environment variables, API docs and tests.
- [ ] Report and deck distinguish implemented features, measured results, targets and roadmap.
- [ ] Demo video shows real running software; no mock API output presented as live inference.
- [ ] Final report, slide deck and ZIP match the official form's naming and file-size requirements supplied by the participant.

## Six-day closeout plan (9–15 November 2026)

| Date | Priority | Exit evidence |
|---|---|---|
| 9 Nov | Freeze challenge scope; run baseline tests; configure secrets locally | Reproducible local setup |
| 10 Nov | Survey the actual AI & ML lab; list zones and assets | Verified inventory sheet and approved photos |
| 11 Nov | Enter assets, upload manuals/photos, approve sources | Asset IDs resolve to records and citations |
| 12 Nov | Test Gemini grounding, abstention, multi-turn flows and tours | Recorded test cases and results |
| 13 Nov | UX/accessibility, security review, error handling, deployment | Working deployed demo or reproducible local demo |
| 14 Nov | Record demo, finish report/deck/manual, clean GitHub | Complete submission package |
| 15 Nov | Final regression and submission before deadline | Submission confirmation |

Do not claim a milestone is complete without its corresponding evidence. If the institution cannot provide real lab data in time, present the configured pilot honestly and demonstrate the admin workflow using clearly labelled sample records—not as actual OIST inventory.
